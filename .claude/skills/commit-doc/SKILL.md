Сделай документацию на основании последнего коммита в формате Markdown
и положи её в папку `docs/tasks`.

Дополнительные указания (например, другой коммит или номер файла): $ARGUMENTS

## Правила

- Имя файла — `PW-<следующий номер>.md`: номер на единицу больше наибольшего
  номера среди файлов `docs/tasks` (у файлов вида `PW-08,09.md` берётся
  последний номер).
- Структура как в последних документах (`PW-85.md`, `PW-86.md`, прочитай
  один из них как образец): заголовок «Документация по коммиту», раздел
  «Коммит» с хешем и сообщением, «Общее описание», затем разделы по сути
  изменений (модель данных, API, фронтенд и т. п.), «Тесты», «Документация».
- Пиши по фактическому diff коммита (`git show`), а не по сообщению коммита.
  Перед описанием изменённого кода прочитай его.
- Если хеш коммита уже встречается в `docs/tasks`, второй документ не создавай,
  а сообщи об этом.
- Если коммит исправляет коммит, уже описанный в `docs/tasks` (сообщение
  `fix: …` по той же теме), спроси, создать ли новый файл или дописать
  раздел «Исправлено после коммита» в существующий документ.
- Текст на русском, в стиле существующих документов.
- Коммит не делай. В конце назови созданный файл.

## Данные

Последние файлы в `docs/tasks`:
!`ls docs/tasks | sort -V | tail -3`

Последний коммит:
!`git log -1 --format='%h %s'`

Изменённые файлы:
!`git show --stat --format= HEAD`
